KOI 💗 — FOUNDATION 2.0 ARCHITECTURE

SOURCE OF TRUTH
Cloud-shared data: Supabase Postgres
Offline / fast local data: browser storage/cache
Static offline content: data/data.js

TENANCY MODEL
User -> pair_members -> Pair
Every shared record carries pair_id.
A user can belong to only one pair in v1.
A pair can contain at most two users.

SECURITY
- Authentication: Supabase Auth.
- Authorization: Postgres Row Level Security.
- Pair joins: SECURITY DEFINER RPC, not direct table insertion.
- Invite codes: one-time, expiring.
- Media: private Supabase Storage bucket.
- Realtime: private pair-scoped Broadcast topics.
- No service-role/secret key in browser code.

REALTIME TOPIC PATTERN
pair:<PAIR_UUID>:little_things

The database emits a Broadcast after Little Things INSERT/UPDATE/DELETE.
Only authenticated members of that pair are allowed to subscribe.

WHY LITTLE THINGS FIRST
It is a simple shared CRUD feature. If:
Phone A creates -> Phone B receives -> Phone B deletes -> Phone A updates,
then Auth + RLS + pair tenancy + writes + reads + realtime have all been proven.
